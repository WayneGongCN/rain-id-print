# GA4 功能使用数据评估

## 结论

GA4 自动采集只能直接覆盖页面浏览、会话、滚动、出站点击等通用行为，不能自动理解“选择高清模型”“使用混合排版”“完成冲印图导出”等产品语义。此类数据原则上需要产品事件埋点。

当前项目已经为题述三个场景实现了前端事件上报，因此基础统计不需要再次开发埋点；还需要在 GA4 后台注册自定义维度、配置探索报表，并统一使用“用户总数”而不是“事件数”作为人数口径。

## 现有事件与可回答的问题

| 业务问题 | 现有事件和条件 | 推荐指标 | 当前边界 |
| --- | --- | --- | --- |
| 多少用户选择了高清模型 | `background_model_change`，`to_model_id = quality` | 用户总数 | 统计成功切换到高清模型的用户；不会记录刷新后沿用本地高清偏好的用户，也不代表实际执行过高清抠图 |
| 多少用户选择过混合排版 | `layout_mode_change`，`layout_mode = mixed` | 用户总数 | 包含用户主动切换和导入多张照片后的自动切换，不等于最终用混排导出 |
| 多少用户用混排完成导出 | `photo_export`，`layout_mode = mixed` | 用户总数 | 事件在 JPEG 生成并调用浏览器下载后发送，是更严格的混排转化口径 |
| 多少用户完成最终排版导出 | `photo_export` | 用户总数 | 表示冲印图生成成功并已调用下载；无法证明用户最终把文件保存到磁盘 |
| 多少用户导出单张规格照 | `photo_spec_export` | 用户总数 | 与整纸排版导出是不同的完成事件 |

## GA4 后台配置

在“管理 → 数据显示 → 自定义定义”中创建事件范围的自定义维度：

- `to_model_id`：目标抠图模型。
- `layout_mode`：排版模式。
- `from_model_id`、`paper_spec_id`、`spec_id`：建议一并注册，便于后续分析切换路径、纸张规格和证照规格。

维度只对创建后的新数据生效，通常需要等待 24–48 小时才出现在常规报表中，不能补算创建前的历史参数。事件名和事件用户数本身仍可在事件报告中查看。

建议把 `photo_export` 和 `photo_spec_export` 标记为关键事件，并在“探索 → 漏斗探索”中配置：

`page_view → photo_import → editor_step_change(to_step = layout) → photo_export`

混排完成率应使用 `photo_export(layout_mode = mixed)`，不要只使用 `layout_mode_change(mixed)`。

## “有哪些用户”的限制

当前项目没有向 GA4 设置业务 `user_id`，并且关闭了 Google Signals。GA4 能按浏览器或设备的匿名标识统计和在 User Explorer 中查看匿名事件时间线，但不能告诉管理员真实姓名、账号或联系方式；同一人在不同浏览器、设备、清理 Cookie 或被拦截统计时可能被视为不同用户。

如果未来站点增加登录体系，并确实需要跨设备去重，应发送内部不可识别个人身份的稳定 `user_id`。不要把手机号、邮箱、姓名或其他个人身份信息发送给 GA4。

## 是否还值得补埋点

若只回答题述三个基础问题，当前事件已经够用。若要回答以下更精确的问题，则建议补充事件或调整现有事件：

- “真正使用高清模型完成抠图/导出的用户数”：在换底成功或导出成功事件上携带实际使用的 `model_id`，而不是只记录模型切换。
- “打开过高级设置但没切换的用户数”：增加 `background_model_settings_open`。
- “最终下载是否真实保存成功”：浏览器下载 API 通常无法可靠确认用户是否完成了系统保存，只能把“成功生成并触发下载”作为可观测终点。
- “当前用户偏好分布”：把当前模型作为低基数用户属性上报并注册用户范围维度；需先明确隐私和保留策略。
