# 可扩展抠图模型选择实现与验收报告

日期：2026-08-12

## 实现结论

H5 平台已将抠图能力抽象为模型描述、推理适配器和注册表。页面通过稳定模型 ID 使用能力，不再感知 IMG.LY 的具体模型参数。

首版内置以下产品档位：

- `fast`：快速模型，默认选择，对应约 40 MB 的本地模型资源。
- `quality`：高清模型，对应约 80 MB 的本地模型资源。

两档均在浏览器本地完成推理。后续新增模型只需实现 `BackgroundRemovalBackend` 并加入注册表，不需要修改页面和渲染分支。

## 关键实现

- 平台初始化时校验空注册表、空 ID、重复 ID 和无效默认模型。
- `prepareCutout`、预览和导出均显式携带同一个模型 ID。
- 每张照片按模型隔离抠图结果、进行中任务和专业微调画布。
- 同照片同模型请求自动合并；IMG.LY 同模型推理在适配器内串行执行，避免复用配置时发生进度回调串线。
- 每张照片最多缓存两个模型结果，使用 LRU 淘汰并释放 Object URL 和 Canvas。
- 全局切换会串行准备全部已换底照片，全部成功后原子提交；失败时保持旧模型和旧预览。
- 删除照片或卸载页面会取消当前切换，无法及时中断的结果通过资源身份和任务版本丢弃。
- 模型选择使用版本化 `localStorage` 键持久化，无效 ID 或存储异常时回退快速模型。
- 页面新增全局“高级抠图设置”折叠面板，只展示产品名称、效果说明和下载量，不展示底层技术模型名。
- 模型切换成功和失败均增加类型约束的 GA4 事件，不携带照片内容。
