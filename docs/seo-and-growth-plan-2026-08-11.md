# 雨邻证照 SEO 与推广执行方案

> 日期：2026-08-11
> 站点：<https://idprint.rainnear.com>
> 目标：先建立稳定收录与可衡量的自然增长，再通过内容和渠道分发放大有效用户。

## 一、结论

雨邻证照已经具备适合自然传播的差异化卖点：免费使用、无需注册、照片不上传、浏览器本地智能抠图、多规格混排、300 DPI 导出。当前增长瓶颈不是产品功能，而是搜索引擎难以在首次抓取时完整理解页面，同时全站只有一个可被发现的 URL，无法覆盖用户对“一寸照排版”“6 寸相纸排版”“证件照换底色”“300 DPI 打印”等不同搜索意图。

执行顺序应当是：

1. 一周内完成技术 SEO、搜索平台接入和匿名转化统计。
2. 将工具页改为可预渲染的搜索落地页，并让编辑器作为交互模块加载。
3. 用 6～10 个高质量场景页覆盖高意图长尾词，不批量制造低质页面。
4. 围绕“小红书/B 站演示 + 知乎问题 + 开发者社区/开源渠道 + 线下打印场景”做种子分发。
5. 根据“搜索曝光 → 访问 → 添加照片 → 成功导出 → 分享”漏斗持续迭代。

不建议一开始投放泛关键词广告。站点目前还没有完整的转化基线，直接买量很难判断流量质量，也会把着陆页和首次模型加载中的问题放大。

## 二、现状审计

### 2.1 已经做得好的部分

- 生产地址使用 HTTPS，HTTP 会 308 跳转到 HTTPS，并启用了 HSTS。
- 页面已有唯一 `h1`、合理的 `h2` 层级、中文 `lang="zh-CN"`、响应式布局和基础描述。
- 首屏交互包约 303 KB（线上压缩传输约 95.5 KB）；23 MB WASM 模型没有阻塞首次页面展示。
- 2026-08-11 移动端 Lighthouse 实测：Performance 100、SEO 100、Accessibility 95、Best Practices 93；FCP 1.4 秒、LCP 1.4 秒、CLS 0、TBT 0 ms。
- “照片仅在本地处理”与“无需上传服务器”是强信任卖点，也能形成区别于服务器端工具的搜索点击理由。

Lighthouse 的 SEO 100 不能理解成 SEO 已完成。它主要检查基础可抓取性，不会评价关键词覆盖、内容深度、站点权威、搜索需求匹配和外链。

### 2.2 需要优先解决的问题

| 优先级 | 问题 | 当前证据 | 影响 |
| --- | --- | --- | --- |
| P0 | 首次 HTML 几乎没有正文 | 线上 HTML 只有空的 `<div id="root"></div>`，正文依赖 React 执行 | 搜索引擎需要二次渲染；中文搜索收录速度和稳定性存在风险 |
| P0 | 缺少站点地图 | `/sitemap.xml` 返回 404 | 搜索平台难以主动发现新增场景页 |
| P0 | 标题没有承接品类词 | 当前为“雨邻证照 · Rainnear Photo” | 新品牌没有搜索量，标题没有明确说明工具用途 |
| P0 | 缺少规范链接和分享元信息 | 没有 canonical、Open Graph、社交分享图 | 可能出现 URL 信号分散，社交分享卡片也缺少吸引力 |
| P0 | 没有搜索与转化数据 | 代码中未发现 Search Console 验证或分析事件 | 无法判断收录、关键词、添加照片和导出转化 |
| P1 | 全站只有一个搜索入口 | 当前只有工具首页 | 无法分别匹配换底、排版、尺寸、打印等不同意图 |
| P1 | 缺少可见的说明和 FAQ | 页面主要是编辑器，只有短卖点 | 用户和搜索引擎都难以验证功能、隐私和使用方式 |
| P1 | 首次使用换底模型较大 | 构建产物中的 WASM 约 23 MB | 移动网络首次换底可能流失，需要测量和预期管理 |
| P1 | 根域异常 | `https://rainnear.com/` 实测返回 Cloudflare 522 | 如果宣传或外链误用根域，会直接损失用户和链接权重 |
| P2 | 可访问性细节 | Lighthouse 报告存在文字对比度、可见标签与无障碍名称不一致、小字号问题 | 影响移动体验，也会间接影响转化 |
| P2 | 缺少 Web App Manifest | `/manifest.webmanifest` 返回 404 | 不影响搜索收录，但不利于“安装到桌面”和复访，可后置处理 |

`robots.txt` 返回 404 通常等同于没有设置抓取限制，并不代表站点被屏蔽；问题在于无法在其中声明 sitemap。应新增明确允许抓取的文件，而不是把 404 描述成索引故障。

## 三、产品定位与关键词

### 3.1 建议定位

主定位：**照片不上传的免费在线证件照排版与换底工具**。

首页不要宣称“生成官方合规证件照”，因为当前产品没有针对具体证件做完整的人脸位置、头部比例、服装、曝光和官方规则校验。更准确的表达是“按常用尺寸裁切、换底和冲印排版”。涉及签证、护照、考试报名等规则时，应引用对应机构的最新官方要求，并明确最终以受理机构为准。

### 3.2 关键词分层

| 搜索意图 | 主要关键词 | 对应页面 | 页面任务 |
| --- | --- | --- | --- |
| 核心工具 | 在线证件照排版、免费证件照排版 | `/` | 解释价值并立即开始使用 |
| 冲印排版 | 证件照打印排版、6寸照片排版、证件照冲印排版 | `/id-photo-print-layout/` | 展示纸张、数量、DPI 和裁切说明 |
| 换底 | 证件照换底色、白底换蓝底、照片背景换色 | `/id-photo-background/` | 强调本地处理、红白蓝灰底和边缘微调 |
| 一寸照 | 一寸照片尺寸、一寸照排版、一寸照6寸排版 | `/one-inch-photo/` | 提供尺寸、像素换算、排版示例和工具入口 |
| 二寸照 | 二寸照片尺寸、二寸照排版 | `/two-inch-photo/` | 同上，避免与一寸页重复套模板 |
| 打印知识 | 300 DPI 是多少像素、证件照怎么打印 | `/guides/print-id-photo-300dpi/` | 解决打印模糊、纸张和缩放问题 |
| 隐私信任 | 证件照在线处理安全吗、照片不上传工具 | `/privacy/local-photo-processing/` | 解释浏览器本地处理、模型下载和数据边界 |
| 多人/混排 | 多张证件照混合排版、不同尺寸照片排版 | `/mixed-photo-layout/` | 突出目前竞品不一定具备的混排能力 |

命名应以用户真实搜索语言为主，不要在标题里堆砌同义词。每个页面必须解决独立问题，有自己的示意图、步骤、FAQ 和工具预设；如果只是替换“一寸/二寸”几个字，就不应发布。

## 四、技术 SEO 改造

### 4.1 首页元信息

建议首页标题：

```text
免费在线证件照排版｜换底色、6寸冲印、300 DPI｜雨邻证照
```

建议描述：

```text
雨邻证照提供免费的在线证件照换底与冲印排版，支持一寸、二寸、多照片混排和 6 寸、A4 纸张，导出 300 DPI 图片。照片只在浏览器本地处理，无需注册，不上传服务器。
```

同时增加：

- `link rel="canonical" href="https://idprint.rainnear.com/"`
- Open Graph 的标题、描述、URL、站点名和 1200×630 分享图
- `twitter:card=summary_large_image`
- `meta name="applicable-device" content="pc,mobile"`，用于明确响应式页面设备范围
- 搜索平台验证标签；验证值通过部署环境变量注入，不提交个人账号密钥

### 4.2 预渲染与内容架构

理想结构是“静态落地页 + React 工具岛”：

```text
搜索引擎/用户
  └─ 预渲染 HTML：标题、卖点、三步教程、尺寸说明、FAQ、隐私说明
       └─ React 工具：上传、换底、排版、预览、导出
```

实施选择：

1. 优先：让首页和内容页在构建时输出完整 HTML，编辑器在客户端激活。
2. 过渡：先建立独立静态内容页并互相链接，随后再改造首页预渲染。
3. 不建议：只把关键词塞进 `noscript`、隐藏文本或生成大量空壳页面。这些做法不能提供真实用户价值。

页面正文建议至少包含：清晰的一句话用途、三步使用方法、支持的规格和纸张、本地处理原理、打印注意事项、真实界面截图、相关页面链接和 4～6 个真实 FAQ。篇幅由问题复杂度决定，不设机械字数门槛。

### 4.3 robots、sitemap 与结构化数据

首版 `robots.txt`：

```text
User-agent: *
Allow: /

Sitemap: https://idprint.rainnear.com/sitemap.xml
```

首版 sitemap 只包含真实、可索引、返回 200、具有独立内容的规范 URL。不要加入带查询参数的编辑器状态 URL，也不要在 sitemap 中提交重定向或 404。

首页添加 `SoftwareApplication` JSON-LD，可包含：

- `name`、`url`、`description`
- `applicationCategory: MultimediaApplication`
- `operatingSystem: Web`
- 免费价格 `offers.price: 0` 与 `priceCurrency: CNY`
- 与页面可见内容一致的 `featureList`

不要虚构评分、评论数、下载量或组织资质。结构化数据必须与用户实际看到的内容一致。FAQ 可以保留为页面语义信息，但不要把获得 FAQ 富结果当作增长目标。

### 4.4 搜索平台接入

完成以下站点验证并提交同一份 sitemap：

- Google Search Console：检查 URL 渲染、索引状态、搜索词、页面体验。
- 百度搜索资源平台：验证 HTTPS 子域，提交 sitemap；新页面发布后按平台配额主动推送。
- Bing Webmaster Tools：可从 Search Console 导入站点，提交 sitemap；内容页更新较频繁后再考虑 IndexNow。

每周检查：已发现 URL、已抓取未编入索引、重复网页、软 404、移动体验、品牌词与非品牌词曝光。单页小站无需过度自动化 URL 推送，先把页面质量做好。

### 4.5 性能和可访问性

- 保持抠图模型按需加载；在用户点击换底前说明“首次需下载本地模型”，并显示真实下载进度。
- 从北京、上海、广州的移动网络监测主页、JS 和模型下载成功率，再决定是否进行付费推广。
- 修复控制台错误、文字对比度、可见标签与无障碍名称不一致、小字号问题。
- 对内容图片使用明确宽高、WebP/AVIF、懒加载；首屏主视觉不要依赖大图。
- `Cross-Origin-Embedder-Policy: require-corp` 可能拦截不兼容的第三方统计脚本。分析工具应走同源或经验证支持 COEP 的加载方式，部署后检查控制台与抠图线程是否正常。

## 五、页面内容模板

以“一寸证件照 6 寸相纸排版”为例：

1. `h1`：一寸证件照怎么排到 6 寸相纸上？
2. 开头直接回答：常用尺寸、300 DPI 对应像素、本站能完成什么。
3. 可视化示例：一寸照在 6 寸纸上的实际排版预览。
4. 三步操作：添加照片 → 选择一寸与 6 寸（4R）→ 导出 300 DPI。
5. 打印提醒：打印时关闭“适应页面/自动缩放”，以实际尺寸输出。
6. 隐私说明：像素数据留在设备，网络请求只用于加载页面和模型。
7. FAQ：能排几张、为什么留裁切间距、手机能否使用、导出为什么是 JPEG。
8. 主要 CTA：带预设打开编辑器；次要 CTA：查看二寸照或混排教程。

每篇内容都应自己实测一遍，并配本站真实界面图。截图比通用图库更能建立信任，也更适合在小红书、知乎和搜索结果中复用。

## 六、推广方案

### 6.1 产品内增长

- 导出成功后提供“复制工具链接”和“分享给需要打印证件照的人”，不在成品照片上强制加水印或二维码。
- 为每个场景页提供可分享的预设链接，例如预选“一寸 + 6 寸（4R）+ 2 mm 间距”；预设参数页仍 canonical 到对应内容页，避免索引大量参数 URL。
- 在成功导出后展示简短反馈：“这次排版是否成功？”只收集结果和匿名错误码，不收集照片、文件名或人脸信息。
- 将“本地处理”做成可点击的信任说明，解释什么会联网、什么不会联网，而不只是一句口号。

### 6.2 内容分发

优先复用同一个真实案例，而不是为每个平台重新生产完全不同的内容：

| 渠道 | 内容形式 | 示例标题 | 目标 |
| --- | --- | --- | --- |
| 小红书 | 6～8 张步骤图或 30 秒录屏 | “一寸照别再一张张打印，6寸相纸这样排” | 获取生活场景搜索流量和收藏 |
| B 站 | 1～3 分钟无废话演示 | “免费把证件照排成 300 DPI 冲印图，照片不上传” | 建立可信演示和长尾搜索入口 |
| 知乎 | 回答已有真实问题 | “如何自己排版一寸证件照并拿去冲印？” | 用完整答案承接问题搜索，不做只贴链接的广告 |
| V2EX/掘金/GitHub | 技术复盘与开源介绍 | “在浏览器本地完成抠图与 300 DPI 证件照排版” | 获得首批反馈、开发者外链和口碑 |
| 微信群/校园群 | 一页图文 + 直达场景页 | 报名季、毕业季、入职材料场景 | 验证高频人群与具体需求 |
| 打印店/照相馆 | 桌面二维码或合作页 | 用户先自助排版，门店负责冲印 | 获取线下高意图用户和真实反馈 |

社区发布必须先提供可独立使用的教程，再自然带出工具；避免批量发相同文案、购买垃圾外链或伪造用户评价。

### 6.3 可持续内容选题

首批建议只做以下 8 个：

1. 一寸照片的毫米尺寸、300 DPI 像素与 6 寸排版。
2. 二寸照片的毫米尺寸、像素与打印方法。
3. 6 寸相纸能排多少张一寸/二寸照。
4. 证件照红底、蓝底、白底怎么换，以及何时必须核对官方要求。
5. 为什么冲印图需要 300 DPI，打印模糊的常见原因。
6. 多个人、不同尺寸如何在同一张相纸混合排版。
7. 在线证件照工具如何做到照片不上传。
8. A4 普通纸与 6R 相纸打印证件照的区别。

后续选题只从 Search Console/百度搜索资源平台真实查询词、站内失败反馈和社区提问中产生。不要根据想象批量扩展到“所有国家签证照”，这类信息更新风险高、校验成本大。

### 6.4 合作与外链

- 完善 GitHub 仓库描述、主页链接、README 截图、topics 和可复现的隐私说明；如果仓库公开，可发布首个稳定版本。
- 给打印店、校园社团、求职资料整理站提供无广告的专属场景页，而不是交换全站链接。
- 寻找“打印教程、报名材料、隐私工具、浏览器端 AI”主题的作者做真实体验；允许对方公开缺点。
- 只有对用户有帮助的资源页链接才值得争取。目录站群、群发评论、隐藏链接和购买外链应全部避免。

## 七、数据与实验

### 7.1 事件设计

在不触碰用户照片的前提下记录：

| 事件 | 含义 | 禁止携带的数据 |
| --- | --- | --- |
| `landing_view` | 进入某个落地页 | IP 明文长期留存、文件信息 |
| `photo_add_started` | 用户主动开始添加照片 | 文件名、图片内容、人脸特征 |
| `photo_add_succeeded` | 本地读取成功 | 原始尺寸可按区间统计，不传精确内容 |
| `model_load_succeeded/failed` | 换底模型加载结果 | 照片和模型输入 |
| `export_succeeded/failed` | 是否成功导出 | 导出图片、文件名 |
| `share_clicked` | 用户点击分享 | 通讯录和接收人信息 |

隐私页应公开说明统计范围。若使用第三方分析服务，需要验证数据地域、Cookie、保留周期和 COEP 兼容性。

### 7.2 核心漏斗

```text
搜索曝光 → 搜索点击 → 页面访问 → 添加照片 → 成功导出 → 分享/复访
```

北极星指标建议使用“每周成功导出的独立设备数”，同时观察：

- 非品牌搜索曝光和落地页数。
- 各查询的平均排名与点击率，按排名区间比较，不设脱离排名的统一 CTR 目标。
- 页面访问到添加照片的激活率。
- 添加照片到成功导出的完成率。
- 模型加载失败率和导出失败率。
- 自然搜索、内容平台、社区、线下二维码各自带来的成功导出数。

前两周只建立基线。之后每个实验只改变一个主要变量，例如标题、首屏 CTA、模型提示或教程示意图，并比较至少一个完整周周期。

## 八、90 天执行计划

### 第 1 周：让搜索引擎看懂并让团队看见数据

- 修正首页 title 和 description，添加 canonical、OG、分享图和 `SoftwareApplication`。
- 新增 `robots.txt` 和 `sitemap.xml`。
- 接入 Google、百度、Bing 站长平台并提交首页。
- 接入匿名事件漏斗，验证不会上传照片和文件名。
- 修复或跳转 `rainnear.com` 根域，所有对外物料统一使用规范地址。
- 修复 Lighthouse 已发现的控制台与可访问性问题。

验收：线上元信息正确；robots/sitemap 返回 200；三个平台至少完成站点验证；从一次真实访问能看到添加照片和成功导出事件。

### 第 2～4 周：建立第一批搜索入口

- 完成首页预渲染或静态落地页架构。
- 上线换底、冲印排版、一寸、二寸、隐私说明 5 个独立页面。
- 每页配真实截图、步骤、FAQ、内部链接和场景预设。
- 发布 2 篇小红书图文、1 个 B 站演示、2 个高质量知乎回答、1 篇技术复盘。

验收：主要正文在关闭 JavaScript 时仍可读取；sitemap 中所有 URL 均为 200 且 canonical 自指；索引覆盖率开始稳定上升。

### 第 2 个月：放大有效内容

- 根据真实查询词补充 300 DPI、6 寸相纸、混排、A4 打印 4 个页面。
- 优化有曝光但点击率偏低的标题和摘要。
- 与 3～5 个校园/打印/求职场景的真实合作方小范围测试二维码入口。
- 优先解决漏斗中最大的流失点，不盲目增加内容数量。

### 第 3 个月：形成复用增长循环

- 将表现最好的搜索问题复用成短视频、图文和 FAQ。
- 为高转化场景增加更直接的预设入口。
- 对比自然搜索、社区、内容平台与线下合作的成功导出成本。
- 只有当“访问 → 成功导出”的漏斗稳定后，才用小预算测试高意图搜索广告，并设置成功导出或导出按钮点击为转化目标。

## 九、暂时不要做的事

- 不购买关键词堆砌文章、站群外链、刷量或虚假评价。
- 不一次生成几百个尺寸/城市/考试模板页。
- 不将分享水印强加到用户导出的证件照上。
- 不为了统计上传文件名、照片、精确人脸尺寸或画布内容。
- 不把 Lighthouse SEO 100 当作排名已优化完成。
- 不在未经官方规则核验时承诺照片“100% 通过审核”。
- 不优先做 `llms.txt`、复杂 IndexNow 自动化或 PWA；它们的收益低于预渲染、内容页和搜索平台接入。

## 十一、建议的第一张执行单

如果只安排一个迭代，建议范围如下：

1. 首页 title、description、canonical、OG、分享图、`SoftwareApplication`。
2. `robots.txt`、`sitemap.xml`。
3. 首页核心介绍、三步教程、支持规格、隐私说明、FAQ 的构建期预渲染。
4. Google/百度/Bing 验证位与匿名漏斗事件。
5. 根域跳转、控制台错误和可访问性问题修复。

完成这一张执行单后，再根据真实数据决定先写“一寸照”内容页还是先优化“换底色”的模型加载体验。
