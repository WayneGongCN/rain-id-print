## 验收结果

| 功能 | 真实图片端到端证据 | 结果 |
| --- | --- | --- |
| JPEG 默认上传 | 1200×1200 人像导入后生成 12 张一寸照片，纸张利用率 68% | 通过 |
| PNG / WebP 上传 | 同时导入人像 PNG 与城市 WebP，页面显示 3 张照片并自动进入混排 | 通过 |
| 拖拽上传 | `dragover` 显示 `is-dragging`，`dragleave` 清除状态，`drop` 后新增真实人像卡片 | 通过 |
| 文件格式限制 | `text/plain` 被拒绝，卡片数量不变，显示“不支持 text/plain 图片格式” | 通过 |
| 8MB 限制 | 9.5MB 城市实拍 PNG 被拒绝，显示“单张图片不能超过 8MB” | 通过 |
| 4000 万像素限制 | 7000×6000、3.8MB 城市实拍 JPEG 被拒绝，显示“图片解码尺寸不能超过 4000 万像素” | 通过 |
| 10 种照片规格 | 一寸、小一寸、大一寸、二寸、大二寸、中国护照、美国签证、日本签证、驾驶证、社保照片逐项生成 Canvas，无错误 | 通过 |
| 8 种纸张 | 5R、6R、7R、8R、10R、A5、A4、A3 逐项生成正确方向与 300 DPI 像素尺寸 | 通过 |
| 单照片自动铺满 | 6R 一寸自动生成 12 张；A4 一寸自动生成 56 张 | 通过 |
| 指定数量 | 指定 8 张后准确排入 8 张，导出按钮可用 | 通过 |
| 溢出处理 | 6R 指定 100 张时排入 12 张、提示剩余 88 张，并禁用导出 | 通过 |
| 多规格混排 | 三张真实照片分别设置一寸×2、美国签证×1、日本签证×3，A4 准确排入 6 张 | 通过 |
| AI 抠图与五种背景 | 同一真实人像依次验证原图、白、蓝、红、灰，预览均重绘且无错误 | 通过 |
| 本地隐私处理 | 城市实拍执行首次抠图换底期间只观察到本地 `blob:` GET，请求数 1，无 POST、PUT 或请求体 | 通过 |
| 裁切间距 | 原生 `input/change` 事件分别设置 0mm 和 10mm，标签同步变化，Canvas 指纹由 `a51f2574` 变为 `f117ae10` | 通过 |
| 分隔线 | 深灰、蓝色、白色的 Canvas 指纹分别为 `0badf476`、`11e42341`、`4c6b208a` | 通过 |
| 删除照片 | 删除 PNG 后资源卡片由 3 张变为 2 张，预览继续正常，无资源不存在错误 | 通过 |
| 单照片 / 混排切换 | 单照片模式正确弱化第二张卡片，混排模式恢复全部卡片并重排 | 通过 |
| 桌面响应式 | 1280px 视口下页面内容宽度未超过视口 | 通过 |
| 移动端响应式 | 390×844 视口下 `bodyScrollWidth=375`，控制区、预览区和导出按钮均位于可视宽度内 | 通过 |
| 300 DPI 导出 | 从页面点击导出成功生成 A4 JPEG，内容为 3 张城市照片和 2 张蓝底抠图人像 | 通过 |

裁切间距用例通过浏览器原生输入事件驱动 React 的 `onChange`，并比较实际可见 Canvas 的像素指纹，避免只验证控件值而未验证重排结果。
