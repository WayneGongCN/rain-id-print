# 证件规格预设与自定义 DPI 实现说明

## 目标与边界

本次改造为 H5 排版流程增加按业务名称选择照片规格的能力，并允许用户自定义整张冲印图的导出 DPI。当前产品仍按“原图处理 → 目标规格裁切 → 纸张排版 → JPEG 导出”一次性完成，不生成可直接上传办证系统的单张电子文件，也不校验头部位置、文件体积、背景色或地方受理规则。

后续拆分单张标准照生成能力时，应继续复用 `@rainnear/core` 中的 `PhotoSpec`，并在独立的电子文件规则中补充精确像素、格式、体积、人像位置和背景要求，避免把这些规则耦合进纸张或 Canvas 平台层。

## 分层设计

- `@rainnear/core`：维护业务规格、物理尺寸、建议 DPI、分组、提示和规范来源；布局算法仍只消费毫米尺寸与全局 DPI。
- `app-h5`：维护用户选择、自动建议、风险提示和导出安全校验，并把选中的规格转换为布局输入。
- `plateform-h5`：继续按 `LayoutPlan.dpi` 创建 Canvas，并把相同 DPI 写入 JPEG 密度元数据，不感知护照或身份证等业务语义。

社会保障卡要求可能因地区和办理渠道不同而变化，界面会提示用户以当地人社部门要求为准。所有证件业务预设仅表示常用物理尺寸和建议冲印精度，不代表照片已经通过官方材料审核。

## DPI 交互规则

- 页面初始值为 300 DPI，允许输入 72–600 的整数。
- 选择建议值更高的业务规格，或切换到包含高建议值照片的混排模式时，只向上提高到当前有效照片中的最高建议 DPI。
- 删除照片、切换为低建议值规格或切回单照片模式时，不自动降低用户当前设置。
- 用户可以主动设置为低于建议值的 DPI；排版和导出仍可继续，但页面显示非阻断风险提示。
- 布局超过 2500 万像素时，在页面上提前阻止导出并说明预计像素量。底层平台仍保留相同限制作为最终防线。
- DPI 不写入本地存储，刷新页面后恢复 300。

## 后续演进

单张标准照生成应建立独立输出请求，直接引用 `PhotoSpec.id`，并把以下能力作为电子文件层配置，而不是继续扩张纸张布局模型：

1. 精确像素或允许的像素区间。
2. JPEG/PNG、色彩空间、压缩质量和文件体积。
3. 背景色、人像位置、头部比例和面部检测。
4. 不同地区、国家、签证类型或线上办理渠道的版本化规则。
5. 单张标准照预览、下载与合规检查报告。
